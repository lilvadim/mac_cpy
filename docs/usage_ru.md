# mac_cpy

[Краткое руководство](../README.md) · [English version](usage.md)

Выборочный бэкап и восстановление домашней папки macOS на Rust. Файлы упаковываются системным `/usr/bin/tar` напрямую в `.tar.gz` в назначении. Вторая локальная копия выбранных данных не создаётся.

В архив входят выбранные файлы, снимки конфигов, манифест Homebrew при его наличии, список приложений, копия `/etc/hosts` и запущенный бинарник `mac_cpy`. Рядом сохраняется файл SHA-256.

Это инструмент переноса файлов, а не загрузочный образ или полная резервная копия системы. Он не устанавливает приложения, не применяет системные настройки и автоматически не заменяет `/etc/hosts`.

## Требования

- macOS и её встроенный BSD tar. Запуск от обычного пользователя; работа от root запрещена.
- Rust 1.88 или новее для сборки. Логика бэкапа не использует Python, Ruby или shell-скрипты; внешние команды запускаются напрямую. У самого Homebrew есть собственные зависимости.
- Homebrew необязателен. Без него копирование продолжается без Brewfile и списка версий. Если Homebrew установлен, ошибки его команд экспорта метаданных останавливают бэкап.
- Существующие домашняя папка и каталог назначения, достаточные права доступа и свободное место.

Цель совместимости Apple Silicon — **macOS 11.0 Big Sur**, заданная в [`.cargo/config.toml`](../.cargo/config.toml). Это параметр сборки, а не утверждение о проверке запуска на Big Sur. Зависимости зафиксированы в `Cargo.lock`. Homebrew и отдельные приложения имеют собственные требования к ОС.

Перед бэкапом закройте приложения и остановите сборки. При выборе данных Firefox или Codex настоящий бэкап проверяет их процессы и требует завершить приложения. Автоматически они не закрываются. В dry-run и metadata-only эта проверка процессов не выполняется.

## Сборка и установка

Команды выполняются из скачанного проекта:

```sh
cargo build --release --locked
./target/release/mac_cpy --help

# Установка бинарника в каталог Cargo, обычно ~/.cargo/bin.
cargo install --path . --locked

# Начальные конфиги без перезаписи существующих персональных правил.
config_dir="${XDG_CONFIG_HOME:-$HOME/.config}/mac_cpy"
mkdir -p "$config_dir"
cp -n exclude.mac_cpy root_exclude.mac_cpy include.mac_cpy "$config_dir/"
```

Добавьте каталог бинарников Cargo в `PATH`. `cargo install` не устанавливает конфиги. Перед первым бэкапом проверьте поставляемые правила: это исходный набор для настройки, а не универсально полный выбор данных.

Можно запускать бинарник из `target/release`. `build.rs` копирует три конфига рядом с debug/release-бинарниками, включая структуру cross-build. Соседние файлы используются только при отсутствии пользовательской папки конфигов.

## Использование

```text
mac_cpy DIRECTORY [--metadata-only] [--home HOME] [--dry-run [-e]]
mac_cpy -r ARCHIVE [--home HOME] [--dry-run]
mac_cpy --finalize ARCHIVE.tar.gz.partial [--dry-run]
```

| Опция | Назначение |
| --- | --- |
| `--home HOME` | Другой home: источник при бэкапе, получатель при восстановлении. По умолчанию `$HOME`. Краткой формы нет. |
| `--restore`, `-r` | Восстановление доверенного архива с соседним `.sha256`. |
| `--metadata-only` | Только манифесты и служебные данные, без файлов home и данных приложений. |
| `--dry-run` | Предпросмотр бэкапа/восстановления; для finalize — проверка без завершения архива. |
| `--estimate`, `-e` | Оценка размера и тест сжатия/записи в dry-run бэкапа. |
| `--finalize FILE` | Проверка и завершение существующего `.tar.gz.partial` без переупаковки. |
| `--help`, `-h` | Опции, поиск конфигов, приоритет и синтаксис правил. |

`--estimate` требует `--dry-run` в режиме бэкапа. `--metadata-only` несовместим с estimate, restore и finalize.

```sh
# Выбор данных и исключения.
mac_cpy /Volumes/Backup --dry-run

# Оценка размера и тест цепочки чтение → gzip → запись в назначение.
mac_cpy /Volumes/Backup --dry-run --estimate

# Создать бэкап или только его метаданные.
mac_cpy /Volumes/Backup
mac_cpy /Volumes/Backup --metadata-only

# Другой источник home.
mac_cpy /Volumes/Backup --home /Users/other --dry-run

# Проверить архив и назначение перед восстановлением.
mac_cpy -r /Volumes/Backup/backup-example.tar.gz --dry-run
mac_cpy -r /Volumes/Backup/backup-example.tar.gz
```

Архив можно создавать и хранить внутри выбранного home. Бэкап исключает только точные пути текущего архива, его `.partial` и `.sha256`, а не весь каталог назначения. **Прежние бэкапы в этом каталоге могут войти в новую копию** по обычным правилам. Восстановление отклоняет план, который перезаписал бы исходный архив или checksum, в том числе через hard link. Эти проверки не защищают от изменений другими процессами после сканирования.

## Конфигурация

Требуются все три файла:

| Файл | Правила |
| --- | --- |
| [`root_exclude.mac_cpy`](../root_exclude.mac_cpy) | Буквальные имена непосредственно в home, например `Library` или `Games`. Обычный обход не заходит в эти корни. |
| [`exclude.mac_cpy`](../exclude.mac_cpy) | Пути и Unix glob-шаблоны относительно home. Совпавшая папка исключается с поддеревом. Поддерживает директиву `@GITIGNORE`. |
| [`include.mac_cpy`](../include.mac_cpy) | Принудительно включаемые пути/glob-шаблоны относительно home. Отменяют исключения выше и `.gitignore`. Включённая папка возвращается целиком. |

Порядок поиска:

1. `$XDG_CONFIG_HOME/mac_cpy`, если `XDG_CONFIG_HOME` непустой и абсолютный. Иначе `~/.config/mac_cpy`.
2. Если пользовательской папки нет — каталог фактически запущенного бинарника.

Существующий, но неполный или ошибочный пользовательский набор останавливает запуск; смешивания файлов из разных мест нет. `--home` меняет данные, а не поиск конфигов. Правила перечитываются каждый запуск и сохраняются в архиве в загруженном виде. Восстановление и finalize не требуют текущих конфигов и не применяют текущие исключения к архиву.

### Приоритет и синтаксис

Обычный выбор начинается с элементов home без `root_exclude`, затем применяются `exclude` и включённые правила `.gitignore`. `include` принудительно возвращает совпавшие пути, в том числе под исключёнными родителями. Порядок строк этот приоритет не меняет. Пересекающиеся выборки архивируются один раз.

Папки home `.mac_cpy_restore` и `.mac_cpy_overwritten`, а также пути текущего архива всегда зарезервированы. Включить их в копию home через `include` нельзя.

Одна строка — один путь или шаблон:

- Пустые строки и строки с `#` после удаления начальных пробелов пропускаются. Начальные/конечные пробелы обрезаются; внутренние сохраняются. Кавычки не нужны.
- `exclude` и `include` поддерживают `*`, `?`, `[abc]`, `[a-z]`, `{a,b}` и отдельный компонент `**` для произвольной глубины. Скрытые имена сопоставляются; регистр учитывается.
- Пути отсчитываются от home. `node_modules` означает только `~/node_modules`, `**/node_modules` — любую глубину.
- Нет shell-подстановок, регулярных выражений, раскрытия `~`, переменных или команд. Абсолютные пути, компоненты `..`, обратная косая черта и управляющие символы запрещены. Требуется UTF-8.
- Отсутствующие включаемые пути и шаблоны без совпадений пропускаются. Поиск include не переходит по ссылкам на каталоги, включая родителей буквального пути; сама конечная ссылка может сохраняться.

```text
# Примеры exclude.mac_cpy
Downloads/*.dmg
myprojects/**/target
**/.DS_Store
@GITIGNORE
```

```text
# Примеры include.mac_cpy
Library/Application Support/VSCodium/User/settings.json
Library/Application Support/JetBrains/*/{options,keymaps,codestyles}
```

### Локальные .gitignore

Точная строка `@GITIGNORE` в `exclude.mac_cpy` включает локальные и вложенные `.gitignore` через библиотеку Rust `ignore`. Глобальные исключения Git и `.git/info/exclude` не загружаются. Удаление/комментирование директивы отключает механизм. Безусловного исключения всех каталогов `target` нет.

Вложенные правила переопределяют родительские. Отрицание `!` не возвращает дочерний файл, пока его родитель остаётся игнорируемым, и не отменяет явные правила `root_exclude`/`exclude`. Для принудительного возврата используйте `include.mac_cpy`. Ошибки загрузки `.gitignore` останавливают запуск.

Директива распознаётся только по полному совпадению обрезанной строки; `./@GITIGNORE` — обычный буквальный путь. Реальный файл, каталог или ссылка `HOME/@GITIGNORE` останавливает бэкап, только если проходит выбор и фильтрацию, в том числе в dry-run; временно переименуйте элемент. Вложенные файлы с таким именем разрешены. Metadata-only эту проверку пропускает.

## Что сохраняют поставляемые правила

По умолчанию выбирается большинство содержимого home, включая dotfiles. Затем конфиги исключают широкие корни и отдельные генерируемые данные. Точные списки находятся в трёх файлах по ссылкам выше.

- `Library` исключена, кроме явных включений: данные Ghostty, `User/settings.json` VS Code/VSCodium, пользовательские шрифты и раскладки, выбранные настройки JetBrains и файлы Firefox.
- Каталоги расширений `.vscode/extensions` и `.vscode-oss/extensions` включены обратно. Горячие клавиши, сниппеты, профили редактора, история и workspace/global storage из `Library` явно не выбираются.
- Для JetBrains включены `options`, `keymaps`, `codestyles`, `templates`, `scratches`, `settingsSync` в совпавших папках приложений/версий.
- Для Firefox включены файлы регистрации профилей, настройки, вкладки/резервные сессии, выбранные данные разрешений/поиска/контейнеров, `chrome`, SQLite/WAL групп профилей. Совпадают все профили стандартной папки `Profiles/*`; внешние пути нужно добавить. Закладки/история, cookies, пароли и расширения явно не включены.
- Исключены Applications, корзина, выбранные корни игр/VM, пути данных Docker, Android AVD, некоторые кеши пакетов и `.codex/tmp`. Универсального распознавания игр/контейнеров нет: другие места подчиняются обычным правилам.
- Каталог установки Homebrew и его `etc` не копируются как отдельные источники. Бинарники приложений в исключённых папках не сохраняются; служебная копия `mac_cpy` входит в архив.

Состав определяется конфигом. Более широкий принудительный include может дополнительно включить кеши, игнорируемые сборки и другие данные приложений.

## Содержимое архива и метаданные

Успешный запуск создаёт:

```text
backup-<date-time>-<pid>-<nonce>.tar.gz
backup-<date-time>-<pid>-<nonce>.tar.gz.sha256
```

Выбранные пути home сохраняют относительную структуру. Служебные файлы расположены в `.mac_cpy_restore/`:

| Файл или каталог | Содержимое |
| --- | --- |
| `FORMAT`, `paths.txt`, `README.txt` | Маркер формата, выбранные корни и инструкция. `paths.txt` не является полным списком файлов. |
| `mac_cpy` и три файла `.mac_cpy` | Бинарник и точные снимки загруженных правил. |
| `MODE` | Только для metadata-only, содержит `metadata-only`. |
| `metadata/Brewfile` | Результат `brew bundle dump`, если Homebrew доступен. |
| `metadata/Homebrew-versions.txt` | Справочный `brew list --versions`; не используется для фиксации версий при восстановлении. |
| `metadata/Applications-not-in-Brew.txt` | Кандидаты для ручной установки; требуют проверки. |
| `metadata/Install-commands.txt` | Ручная установка Homebrew, PATH и применение Brewfile; установка rustup при наличии записей `cargo` в сгенерированном Brewfile. Ничего не исполняется автоматически. |
| `metadata/hosts`, `metadata/macos.txt`, `metadata/source.txt` | Доступный `/etc/hosts`, версия работающей системы и сведения об источнике. |
| Необязательные отчёты в `metadata/` | `skipped-paths.txt`, `gitignored-paths.txt`, `excluded-for-run.txt`. |

Метаданные описывают работающий Mac даже при другом `--home`. Без Homebrew вместо его манифестов создаётся `Homebrew-unavailable.txt`. В списки пакетов/приложений могут входить игры и Docker, даже когда их данные исключены.

Список приложений строится из `/Applications` и `~/Applications` с вложенностью в одну папку. Из него вычитаются имена cask `app` и записи `mas` сгенерированного Brewfile. Для cask с `pkg` выражения `uninstall.pkgutil` находят установленные квитанции; `pkgutil` предоставляет пути приложений относительно места установки пакета. Это учитывает, например, Karabiner-Elements. Нечитаемая квитанция даёт предупреждение и оставляет кандидатов видимыми. Пакеты без выражений квитанций, отличающиеся имена App Store и системные приложения, представленные в `/Applications` (например Safari), всё ещё могут попасть в список. Это не точная база происхождения приложений.

## Бэкап и целостность

1. Обход выбранных путей, сбор метаданных и пробное открытие обычных файлов для проверки чтения без чтения содержимого. Символические ссылки сохраняются как ссылки, внешние цели не обходятся.
2. Проверка процессов выбранных приложений и сбор метаданных в локальный временный каталог.
3. Запись точного результата сканирования и служебных данных напрямую в `.tar.gz.partial` в назначении. Снимок файловой системы не создаётся: между сканированием и упаковкой данные могут измениться.
4. Чтение архива для проверки tar/gzip и обязательных служебных записей, затем отдельное чтение для SHA-256. Запись checksum и переименование завершённого архива.

Системный tar использует PAX, `--mac-metadata` и `--xattrs`. Метаданные находятся внутри архива: сам архив можно хранить на exFAT, SMB или сервере Linux. FAT32 ограничивает размер отдельного файла. Восстанавливать нужно в macOS на файловую систему с нужными метаданными, обычно APFS.

Обнаруженные при сканировании ошибки доступа/чтения метаданных пропускают файл или поддерево только для текущего запуска. Предупреждения содержат полные пути; они повторяются в итоговом `SKIPPED PATHS` и сохраняются в отчёте архива. `DONE WITH SKIPS` завершается с кодом 0, но не означает полную копию выбранного набора. Недопустимые пути/конфиги, ошибки `.gitignore`, ошибки во время tar, нехватка места и ошибки проверки остаются фатальными.

Архивы **не зашифрованы** и могут содержать секреты. SHA-256 обнаруживает изменение относительно соседнего checksum, но не удостоверяет автора и не доказывает полноту данных. Храните оба файла вместе и восстанавливайте только доверенные архивы.

Если хранилище явно не поддерживает синхронизацию записи, программа предупреждает и продолжает без подтверждения физической записи. Другие ошибки синхронизации остаются фатальными. Предупреждения tar о метаданных не подавляются.

### Завершение partial

```sh
mac_cpy --finalize /Volumes/Backup/backup-example.tar.gz.partial --dry-run
mac_cpy --finalize /Volumes/Backup/backup-example.tar.gz.partial
```

Finalize проверяет tar/gzip и обязательные служебные записи, вычисляет SHA-256 и завершает существующий файл без переупаковки. Ссылки вместо входного файла и существующие конечный архив/checksum отклоняются. Dry-run проверяет без создания checksum и переименования. Команда не восстанавливает потерянные файлы и не доказывает, что прерванный запуск сохранил всё нужное. После ошибки или прерывания может остаться `.partial`; само его наличие не означает готовый бэкап.

## Восстановление

Чтение идёт непосредственно из указанного архива: предварительного копирования на внутренний диск и распаковки во временное дерево нет.

1. Проверка SHA-256 по соседнему `.sha256` и маркера формата.
2. Чтение исходного списка путей и отдельного индекса типов/ссылок tar/mtree, их сопоставление. Отклоняются небезопасные/повторные пути и недопустимые родители.
3. Проверка назначения и защита исходного архива/checksum. До замены файлов home существующие заменяемые элементы, кроме каталогов, сохраняются в `~/.mac_cpy_overwritten/before-<stamp>.tar.gz` с исходной относительной структурой. Обычные файлы сохраняются и при совпадении содержимого.
4. Распаковка в home со слиянием настоящих каталогов. Файлы назначения, отсутствующие в архиве, не удаляются.

Ошибки предварительной проверки не создают папок восстановления и не заменяют файлы home. Это не гарантирует успех последующей записи. Восстановление **не является транзакцией**: ошибка ввода-вывода, отключение питания или изменение назначения другим процессом могут оставить частичный результат. Автоматического общего отката нет. Для отдельных файлов используется `--safe-writes`, если системный tar его поддерживает; на старых версиях работа продолжается с предупреждением.

Ссылки с точно совпадающим текстом цели остаются без изменений. Отличающиеся конечные ссылки могут заменяться архивными файлами/ссылками; обычный файл может заменяться архивной ссылкой. Ссылка в родительском каталоге, ссылка вместо требуемого архивом настоящего каталога или конфликт типов файл/каталог останавливают предварительную проверку. Текст `file` и `./file` считается разным.

Восстанавливаются режимы доступа и поддерживаемые системные метаданные; исходные UID/GID не назначаются (`--no-same-owner`). ACL, права, свободное место и форматы данных приложений могут влиять на перенос. Совместимость данных новой версии macOS/приложения со старой не гарантируется.

Этапы checksum, формата, индекса и распаковки требуют нескольких чтений архива. При медленной флешке/сети предварительное копирование архива и checksum на быстрый локальный диск может ускорить восстановление, если хватает места. Перед стиранием исходной системы сохраните отдельный бинарник или проект; иначе для первого запуска нужно вручную извлечь `.mac_cpy_restore/mac_cpy`.

Старые архивы с другими служебными именами (например `.macos-copy-info`) текущим читателем не поддерживаются. Для них используйте соответствующий прежний бинарник.

После восстановления просмотрите `~/.mac_cpy_restore/metadata/Install-commands.txt`, установите приложения отдельно и вручную сравните hosts:

```sh
brew bundle install --file="$HOME/.mac_cpy_restore/metadata/Brewfile"
diff -u /etc/hosts "$HOME/.mac_cpy_restore/metadata/hosts"
```

Список версий пакетов справочный; Brewfile устанавливает доступные пакеты согласно своим записям и поведению Homebrew. Keychain/пароли и оригиналы файлов, находящиеся только в облаке, требуют отдельной подготовки.

## Прогресс и оценки

В интерактивном терминале блок прогресса с рамкой обновляется на месте. Предупреждения остаются над ним, пропущенные пути перечисляются в конце. Без TTY и при `TERM=dumb` используются обычные итоги этапов без управления курсором.

Полное число элементов при сканировании заранее неизвестно. Упаковка, проверка и распаковка считают события tar, включая каталоги и служебные записи. Их процент и ETA этапа основаны на количестве элементов: один большой файл может задерживать процент и увеличивать ETA. SHA-256 считает прочитанные байты.

При создании архива фоновый расчёт использует сохранённые метаданные завершённого сканирования, без повторного обхода home и тестового сжатия. `Total size (uncompressed)` включает приблизительный запас на заголовки/метаданные. `Estimated archive` предполагает **70%** от этого размера после gzip — это условная оценка места, не измеренная степень сжатия.

`--dry-run` показывает выбор и исключения. При `@GITIGNORE` дополнительно обходит выбранные пути и перечисляет игнорируемые элементы. Без директивы обычные данные полностью не сканируются, кроме проверки выбранного конфликтующего имени директивы. Экспорт Homebrew и запись архива в назначение не выполняются.

`--dry-run --estimate` выполняет полный обход и считает размер без перехода по симлинкам и повторного учёта данных hardlink. Тестирует системный tar/gzip напрямую во временный архив в назначении: до 64 целых файлов размером не больше 8 МиБ каждый, суммарно около 64 МиБ. Если подходящих данных меньше 1 МиБ, время не оценивается. Изменения файлов/resource forks могут превысить приблизительный предел. Оценивается создание, без финальной проверки и SHA-256. Измеренное сжатие выборки не заменяет фиксированную оценку места.

Тестовый файл удаляется после обычного завершения, ошибок и обработанных SIGINT/SIGTERM; принудительное завершение или отключение питания могут оставить его. В отличие от простого dry-run, estimate временно пишет данные и читает содержимое файлов. Чтение облачных файлов может инициировать загрузку.

## Разработка

```sh
cargo fmt --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked
```

Тесты используют временные home, искусственные данные, mock Homebrew и настоящий системный tar. Проверяются выбор, приоритет конфигов, оценки, checksum, бэкап/восстановление, ссылки, метаданные, права, предварительные конфликты и сохранение заменяемых файлов. Это не проверка переноса всей реальной системы и не гарантия совместимости версий приложений.

Основные модули: `scan` собирает файловые метаданные; `policy`, `patterns`, `includes`, `gitignore` отвечают за выбор; `estimate` использует результат обхода; `metadata` и `pkg_inventory` собирают манифесты; `archive` и `restore_plan` реализуют бэкап/восстановление; `process`, `progress`, `storage` отвечают за команды, вывод и синхронизацию.
